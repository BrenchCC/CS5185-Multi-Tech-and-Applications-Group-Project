## 一、项目目标与任务

### 1.1 背景与动机

视频编码的目标是在维持视频传输质量的同时，降低传输所需码率。不同视频的画面变化程度不同：幻灯片、演示或固定机位场景中的大部分区域变化很小；其他视频可能包含人物走动、镜头移动和场景切换。体育比赛和快速运动镜头的相邻帧差异通常较大。因此，一套编码参数难以对所有内容都达到最优，不同内容类型需要适合自身特点的编码配置。

本项目要求构建内容自适应视频编码系统，根据视频内容自动选择编码参数。一种可行设计是在编码后检查压缩文件大小和重建质量，必要时自动调整参数并重新编码。目标是在给定压缩比例下，尽可能提高编码视频质量。

例如，固定机位的城市景观变化较小，但需要保留建筑边缘；足球比赛的球员快速移动，相邻帧的多个区域变化明显。同一套参数对不同内容可能产生不同压缩效果。

### 1.2 任务要求

构建可运行的自适应编码系统，将提供的 12 个无音轨 `.mp4` 视频分别压缩到原文件大小的 **5% 和 2%**。

系统可以先分析原始内容，根据目标大小和时长计算目标视频码率，再自动确定 x264 编码参数，通过 FFmpeg 生成压缩码流。随后检查实际大小和质量，必要时调整参数。完整流程包括内容特征分析、参数决策、FFmpeg 编码、结果检查和反馈调整。

各组可以使用规则、公式、加权评分、候选参数搜索、深度学习模型、LLM、多模态 LLM 或组合方法，但必须充分说明选择依据。

最终成果包括从压缩码流解码得到的可播放、完整时长视频，以及说明系统设计、最终编码策略和解码结果主观比较的报告。本项目只涉及 **x264 参数选择**，不修改 x264 源代码。所有编码和封装必须使用 FFmpeg。允许使用 LLM 辅助编程和写作。

### 2.2 内容特征分析

各组可以自行选择视频内容分析方法，例如帧间差异、运动强度、边缘或纹理复杂度、场景切换、局部亮度变化。也可以用预训练神经网络或视觉大语言模型（VLLM）提取特征。分析范围可为整段视频、视频片段或时间窗口。

报告应说明分析方法，以及分析结果如何帮助后续参数选择。项目不限制特征数量、类型或具体计算方法，关键是分析结果确实参与编码决策。

### 2.3 参数决策

系统应结合目标大小和内容分析结果生成编码方案，并调用 FFmpeg 中的 x264 完成压缩。可选参数包括 preset、CRF/CBR/CQP 模式、目标码率、量化参数、关键帧间隔等。

各组自行设计内容到参数的映射，例如根据运动程度调整码率，或让 LLM 作为判断器直接输出 FFmpeg 参数。报告应说明使用哪些参数、如何调整，以及采用规则、公式、搜索或模型的原因，并展示对应参数和压缩结果。项目不统一规定决策方法，要求内容分析与参数选择之间的联系清楚、合理。

### 2.4 FFmpeg 编码与反馈调整

所有编码和封装必须使用 FFmpeg。原视频压缩为二进制码流后，检查实际文件大小；若超出目标，根据设计规则调整参数并重新编码。建议最多进行 **2–3 轮调整**，保存每轮参数、实际码流大小和调整原因。

最终码率收敛到目标后，用 FFmpeg 解码二进制码流并恢复为 `.mp4`。输出必须可播放且时长完整。**不得通过缩短视频或删除内容满足大小限制。**

### 2.5 结果分析

以课程提供的原视频作为参考，展示至少三个视频的原始版本、统一基线结果和自适应结果。每个视频都测试 5% 与 2% 两个目标，并报告以下内容。

- 目标大小、实际大小，以及目标码率和实际码率。
- 主要 FFmpeg 参数和运行时间。
- 相同时间位置的代表帧或短片段。
- 内容特征时间线或曲线，并选择一段解释检测到了什么内容、采用了什么参数、为何采用这些参数。

评价包括是否达到目标大小、能否完整播放、运动是否流畅，以及是否出现明显模糊、块效应、重影或细节损失。必须同时使用 **PSNR 和 MS-SSIM**，结合局部画面观察分析质量。

### 2.6 允许使用的工具

所有视频编码和封装使用 FFmpeg。FFprobe、Python、OpenCV、NumPy 及已有库可用于读取元数据、计算特征、质量评价和生成日志，但不得用其他视频编码器替代 FFmpeg。界面可以是命令行工具或简单桌面应用，无需 Web 部署或实时处理。允许使用 LLM 辅助编程和写作。

## 三、评分与交付

### 3.1 评分标准

评分重点是系统完整性、实验分析和报告的可理解性与可复现性。最终数值表现占总分 10%，压缩质量、码率和文件大小的绝对水平并非主要评分依据。核心是系统按设计运行，并用充分证据解释结果。

| 评分项 | 权重 | 主要标准 |
| --- | --- | --- |
| 系统功能完整性 | 35% | 完成内容分析、参数决策、编码、结果检查和反馈调整，程序运行稳定。 |
| 实验设计与分析 | 25% | 覆盖不同内容，基线公平，分析参数、特征和结果之间的关系，并解释案例。 |
| 报告清晰度与可复现性 | 20% | 清楚说明任务、方法、流程、参数、实验设置、结果和局限，代码及步骤便于复现。 |
| 展示与团队协作 | 10% | 清楚展示完整流程，报告说明清晰。 |
| 结果表现 | 10% | 文件大小控制、PSNR、MS-SSIM 和主观质量。 |

### 3.2 提交材料

1. **可运行代码：**包含依赖、启动命令、FFmpeg 版本及调用方式、输入约束，能够复现从输入到输出的完整流程。
2. **项目报告：**说明系统流程、特征算法、参数决策、反馈调整、实验结果、局限、成员贡献，以及第三方图片和工具来源。
3. **实验结果：**至少三个解码视频的参数与结果、代表截图或短片段，以及支持参数决策的可分析材料，例如特征曲线、调整日志和数据集视频标识。
4. **展示材料：**约 5–6 页幻灯片，展示系统流程、结果和简要分析。

### 3.3 最终展示

每组展示 **5 分钟**，重点说明某个视频如何触发具体决策，以及这些决策带来了哪些可观察变化。评价主要考虑系统完整性、策略与课程知识的联系、实验公平性及解释清晰度。展示安排在 **第 13 周**，需要比较基线与自适应结果，并讨论局限。

### 3.4 四周计划

| 时间 | 主要任务 |
| --- | --- |
| 第 1 周 | 理解内容变化与编码效果的关系，选择特征和规则，准备数据，运行统一 FFmpeg 基线。 |
| 第 2 周 | 实现元数据读取、视频特征分析、时间线可视化和初步参数决策。 |
| 第 3 周 | 完成编码、超限调整及三类视频测试，分析成功和失败案例。 |
| 第 4 周 | 修复问题，整理代码、日志和结果，完成报告、课件与展示排练。 |
