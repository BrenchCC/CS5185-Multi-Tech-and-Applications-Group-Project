# 自适应视频编码实验台开发计划

先完成本地规则和英文 TUI，再接入 Ark 并维护中文提示词及使用指南。实际状态以 `update.md` 与运行证据为准。

## 一、阶段

| 阶段 | 实施内容 | 完成条件 |
| --- | --- | --- |
| P1 环境与测量 | 核验cs_hw、FFmpeg/libx264、12个输入和指标 | 元数据哈希核对；自身比较；错位或缺帧拒绝 |
| P2 编码核心 | 两组固定基线、预算、双遍、三次尝试、独立日志 | 实际编码成功；超预算、失败及取消路径验证 |
| P3 规则校准 | 特征时间线、48个候选任务、阈值搜索、按视频留一 | 保存候选实测结果及冻结policy，说明选择依据 |
| P4 英文TUI | 四页交互、后台消息、进度、取消和历史结果 | Pilot与真实终端检查，普通操作不需命令参数 |
| P5 开发集验证 | 冻结规则后独立执行36个任务，导出结果和图表 | 所有任务状态明确；至少三视频两预算同帧比较 |
| P6 后续课程交付 | 首批保留集 05、06、09；课程报告和展示 | 先交付两档预算各三组对照及 05 的 2% Ark 独立案例，逐轮记录见[首批实验](../../experiments/heldout_pilot/README.md)；已准备[12 个视频的全量实验](../../experiments/full_exps/README.md)，正式编码及最终报告待完成 |

P1和P2先核验，P3校准依赖实测指标正确；P4可与长时间实验交错推进。P5必须在policy冻结后执行，不复用校准编码结果。默认单任务顺序运行、统一两编码线程，减少耗时对照的资源争抢。

## 二、方法与接口冻结

参数仅为medium/slow及AQ1/2。preset和AQ各使用单阈值规则，枚举特征、阈值中点、方向和常量。有效率优先，随后MS-SSIM、PSNR、编码时间和规则复杂度；质量差异容差为0.0001及0.01dB。按视频共同留出两个预算，再用完整开发集冻结。

界面和自动化共用服务。默认轮次为规则、规则、LLM，另有纯 LLM 和纯规则。模型只在到达 LLM 轮时请求，每轮最多一次。大小反馈由程序修正码率，模型不能修改编码命令或运行上限。

输入、特征算法、质量口径和运行配置均需可追溯。数值表现改善不是验收前提，不隐藏失败或质量下降。图表和用户提示使用英文，内部维护使用中文。

## 三、验证和交接

单元与故障检查覆盖预算整数取整、参数白名单、规则边界、超限修正、三次耗尽、双遍失败、取消、pass日志隔离和完整性拒绝。TUI覆盖页面切换、终端缩放、输入校验、防重复运行、进度与错误状态。实际视频编码和指标证据与mock测试分列。

完成阶段后更新状态记录。英文方法见 adaptive_encoding_method，用户操作及结果观测见中文使用指南。每次实验保存配置与证据，正式保留集运行前核对策略与代码冻结状态。
