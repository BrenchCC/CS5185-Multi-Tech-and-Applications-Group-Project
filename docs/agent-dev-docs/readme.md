## 二、输入与闭环

输入为根目录 `CS5185_Project_Video_Dataset/`。预检核对12个视频的元数据、实际字节数与SHA-256。01、02、03、04、07、08为开发集；05、06、09、10、11、12保留至策略冻结后测试。预检可以核验保留集，但校准和本轮验证不得使用其内容特征或输出质量。

预算按原文件字节数的整数百分比向下取整。初始视频码率为 `floor(0.98 * 8 * target_bytes / duration_s)`，输出超限时用附录的比例公式下调。每个配置最多三次双遍尝试，两遍计一次；每次读取原始输入。达标即停止，硬性编码、完整性或评价错误明确失败。各任务与尝试具有独立输出、pass日志，不覆盖既有候选。

程序依次执行元数据读取、特征提取、一次参数决策、双遍编码、大小和完整性检查、质量测量、必要的码率修正和记录。所有编码及封装经 FFmpeg/libx264 完成，不裁剪、丢帧或缩短时长。

## 三、决策与实验

三组对照为固定 `medium/AQ 1`、固定 `slow/AQ 1`、规则自适应。四种候选为 `medium/slow × AQ 1/2`，其他参数保持preset默认并统一线程数。

特征在320×180灰度分析帧上实测：归一化相邻帧平均绝对差、固定Canny阈值100/200的边缘密度，保存逐帧时间线、均值和P90；仅均值与预算对应的每像素每帧比特数进入决策。分析缩放不改变编码和质量评价分辨率。信号不是语义运动或场景切换检测。

开发集四种候选、两种预算共48个校准任务。preset与AQ各搜索一个单阈值规则，包括常量、三种输入特征、相邻实测值中点及双向分支。优先有效任务数、MS-SSIM、PSNR、编码时间及简单规则；质量容差0.0001和0.01dB为工程默认值。按视频留一，两个预算共同留出；记录相对有效最佳候选的质量损失，再由全部开发集生成冻结规则。不强求规则包含分支。

随后独立运行六个开发视频、两个预算和三组共36个验证任务。校准成本单列，验证不复用校准输出或编码耗时。本轮最多84个配置任务，重试另计，不以开发结果声称保留集泛化，也不要求自适应全部优于基线。课程最终全量三组实验仍为72个配置任务，需后续明确执行范围。

## 四、界面与接口

`python main.py` 默认进入英文Textual界面，包含环境数据、任务配置、运行监控和结果查看。支持键盘与鼠标、后台工作、实际编码进度、取消、退出确认、历史结果和CSV导出。默认单次只执行一个任务，避免争抢资源。无已知进度的阶段显示活动状态；后台线程通过消息更新UI。

默认策略按规则、规则、LLM 顺序，另有纯 LLM 和纯规则。每轮一次决策，最多三轮，首次达标结束。规则轮使用冻结策略，模型收到数值特征、预算和此前尝试摘要，只返回 preset、AQ 和英文理由。请求或解析失败消耗一轮，无 SDK 重试和隐式回退。

## 五、评价与交付

完整解码、分辨率、帧率、帧数、相对PTS及结束时间检查通过后，才比较全序列；时间容差为输入输出较大time-base tick，加1微秒十进制序列化余量。不得静默比较共有前缀。

PSNR在原分辨率原生Y平面上累计全部像素误差后取对数。MS-SSIM使用pytorch-msssim 1.0.0，五尺度、单Y通道、范围255、11窗口、sigma1.5、默认K及明确记录的五尺度权重，逐帧算术平均。参考自身比较应为无限PSNR、MS-SSIM接近1，不用普通SSIM替代。

记录完整MP4与视频包大小对应的码率、输入输出哈希、规则版本、命中依据、全部命令、返回结果、每次尝试和阶段耗时。严格JSON用null与显式标志表示无限PSNR。模型决策耗时单列，校准成本与运行决策成本区分。

交付英文代码使用说明、方法、实际结果、CSV/JSON记录、特征曲线，以及至少三个开发视频在两种预算下的相同帧对比。最终课程报告、幻灯片及保留集实验尚不在本轮交付范围。依赖安装与Python执行使用已确认的 `cs_hw`，README命令保持环境无关。
